# V0.9.1 dashboard correction

Scope: dashboard and navigation presentation (FHQ-01.1, FHQ-01.2, FHQ-08.1, NFR-01). Continues on feat/v0.9-dashboard-navigation.

The home screen has a compact brand/profile header, a welcome card using the existing profile's rank and Service, an actionable “Ask a military question” entry to the existing JSP finder, and four cards retained in a two-column layout on mobile:

- Policy — Find JSP answers: existing JSP finder.
- Claims — JPA guidance: existing entitlements explorer, without adding a claim workflow or claiming submission capability.
- Money — Pay and pensions: existing pension/pay planner; budget and savings remain under Money tools.
- Career — Personal development: existing career planner; achievement assistant remains under Explore tools.

The native `st.bottom` container hosts compact Home / Explore / Money / Profile controls. Streamlit reserves space for this container; no fixed/sticky positioning, DOM injection or JavaScript navigation is used. Streamlit 1.67 or later is required and declared in requirements.txt. Bottom placement follows Streamlit's viewport/keyboard behaviour, rather than promising native Android tab behaviour. Scoped CSS sets typography, touch size and the dashboard's two-column layout; it does not position navigation. The full section selector is in the optional sidebar, alongside the existing privacy warnings. Explore and Money expose their secondary tools in a collapsed disclosure.

The original eight tool bodies, including profile onboarding, budget, pay, pension and policy logic, are unchanged byte for byte. Input retention uses the existing V0.8 mechanism. No new policy references, accounts, permanent storage or calculation changes.

Validation commands:

- `.venv/bin/python -m unittest discover -s tests -v`: 24 tests, including existing calculation and session tests, destination synchronisation, four card routes and policy entry.
- `.venv/bin/python -m pip check`.
- `APP_URL=http://127.0.0.1:8503 CHROMIUM_PATH=/usr/bin/chromium node tests/browser_smoke.cjs`: 360px, 390px and 1280px. Checks all sections, no horizontal overflow, bottom-navigation size/access after scrolling, touch targets, visible branding, 2×2 cards, useful card routes, policy entry, retained inputs, dates and edited downloads. Screenshots: `/tmp/forces-hq-phase1/home-360.png`, `home-390.png`, `home-1280.png` and existing interaction screenshots. Local artifacts are ephemeral.

Physical Android still needs Chrome toolbar/keyboard resizing, focus scrolling, text scaling, touch accuracy and session lifecycle checks. Emulation is not physical-device acceptance or WCAG certification.

No merge, publish, deployment or next-phase work. Rollback: revert the dashboard-correction commit after review.
