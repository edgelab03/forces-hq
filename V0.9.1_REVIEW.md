# V0.9.1 dashboard and navigation review

Scope: FHQ-01.1, FHQ-01.2, FHQ-08.1 and NFR-01. Main's PRODUCT_SPEC.md and REQUIREMENTS_TEST_MATRIX.md were read before implementation.

Home now shows a concise linked demo-profile summary, a policy-question entry point and four quick-access cards. Existing profile insights and the complete tool list remain under a collapsed disclosure. The four primary destinations use native Streamlit radio controls in the existing sticky navigation container:

- Home: dashboard
- Explore: entitlements, JSP finder, career, achievement assistant, life and future
- Money: budget/savings and pension planner
- Profile: existing profile workflow

Every primary destination is one tap away. The all-sections selector and sidebar remain synchronised, and grouped shortcuts are available under Explore/Money tools. Input retention continues to use the existing session mechanism.

The maintainable fallback is a sticky top bar rather than fixed bottom positioning. It uses native controls and avoids overlaying forms or the mobile keyboard. The sticky wrapper CSS depends on Streamlit's container structure and should be retested after Streamlit upgrades. No custom JavaScript navigation, storage, accounts, policy references, calculations or profile onboarding changes were introduced.

Validation: `python -m unittest discover -s tests -v` passed all 23 tests, including the original 20 unchanged tests. `python -m pip check` passed. The browser suite covers all nine sections at 360px, 390px and 1280px, scroll persistence, no document overflow, retained budget/achievement inputs, date controls and edited downloads; new checks exercise every primary destination, minimum 44px touch targets and the home policy entry. Screenshots are generated under `/tmp/forces-hq-phase1`; these are ephemeral local artifacts.

Physical Android remains required: Chrome toolbar collapse/expansion, on-screen keyboard and focus scrolling, touch accuracy, text scaling and back/refresh behaviour. Emulated viewports do not establish real-device acceptance or WCAG conformance. Session data still resets when the Streamlit session is lost.

No merge, publication or deployment. Roll back this work with a revert of the V0.9.1 commit after review.
